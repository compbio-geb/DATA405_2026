0 · The coin, the p-value, and the burden of many tests

Before any genomics: three ideas, each with an experiment you can run here.

Nothing about the coin changes between experiments; the spread is what randomness looks like. A read covering a heterozygous site is the same coin: each read comes from one of the two chromosomes.

Is this coin fair? — the p-value

I flip a coin 10 times and get 9 heads. Null hypothesis: the coin is fair. p-value: how often a fair coin gives a result at least this extreme (9 or 10 heads, or by symmetry 0 or 1).

Python

R

p ≈ 0.02: chance alone does this about twice in a hundred. It is a statement about the data given the null, not the probability that the coin is fair.

Twenty candy colours, 19,271 genes — the burden

Test 20 candy colours for a link to acne when none exists: each test has a 1-in-20 chance of a false alarm, so the chance that at least one colour “wins” is 1 − 0.95²⁰ = 64 %. Now do it for every gene:

Python

R

Under the null, p-values are spread evenly: about 5 % fall below 0.05 — 800–960 false “discoveries” with nothing going on. Two ways to pay:

  • Bonferroni — control the chance of any false alarm: threshold 0.05 / 19,271 ≈ 2.6 × 10⁻⁶. Right for 20 candy colours; throws away almost everything in a genome.
  • False discovery rate (Benjamini–Hochberg, 1995) — control the fraction of false alarms in your list. Sort the p-values; the k-th smallest is kept if p₍ₖ₎ ≤ q·k/n. “Of the genes I call, about 5 % are expected to be false” — a promise about the list, not about one gene. p.adjust(p, "BH") returns the smallest FDR at which each gene would be kept (DESeq2’s padj).

1 · Sequencing is sampling

A sequencer does not measure a gene’s expression; it draws reads at random from a pool of molecules. Every number in genomics is therefore a count from a random sample, and every claim needs a probability model.

Three distributions cover most of genomics:

Question Model Where
Of n reads at a site, how many carry allele A? Binomial(n, θ) genotyping, allele-specific expression, RNA editing
How many reads land in a window / on a gene? Poisson(λ) coverage (Lander–Waterman), ChIP-seq peaks (MACS)
Same, but across biological replicates? Negative binomial(μ, α) RNA-seq differential expression (DESeq2, edgeR)

Negative binomial: replicates are noisier than Poisson

For a Poisson variable, variance = mean. Look at the four control samples of the airway experiment.

Python

R

95 % of genes have variance above the Poisson line. The extra variance is biological (four different people). The negative binomial adds one parameter, the dispersion α: variance = μ + α μ². DESeq2’s job is to estimate α for every gene from only a handful of replicates.

2 · Estimation: likelihood and the EM idea

Maximum likelihood. Given data, choose the parameter that makes the data most probable. For a binomial with 54 of 138, the MLE is θ̂ = 54/138 = 0.39 — the obvious answer, now justified.

Bayes. Multiply the likelihood by a prior and normalize: with a flat prior, θ | data ~ Beta(54 + 1, 84 + 1). Now we can ask P(θ > 0.5), which a p-value cannot answer. Section 6 uses exactly this.

EM. When some data are hidden (which transcript did a shared read come from?), alternate: E-step — assign hidden labels in expectation using the current parameters; M-step — re-estimate parameters from the assigned data. Repeat until nothing changes.

EM in ten lines (the RSEM idea)

Two transcripts, A and B. 6 reads map only to A, 2 only to B, 4 map to both. What are the abundances?

Python

R

Naive “split 50/50” gives A = 8/12 = 0.667. EM converges to 0.75 / 0.25: because A is more abundant, the shared reads more likely came from A, which makes A more abundant still — until the answer is self-consistent. This is what RSEM does across all isoforms of all genes with all multi-mapping reads; its expected_count column is the E-step’s final assignment (which is why chr22_expression.tsv has counts like 317.84).

4 · Testing: from one t-test to DESeq2

What a t-test assumes that counts violate: normal errors with equal variance, independence between the 8 samples (but samples come in 4 donor pairs), and one test at a time.

What DESeq2 does (Love, Huber & Anders, Genome Biology 2014):

  1. Model each gene’s count as NB(μ, α) with log μ = log(size factor) + β·design. The design ~ cell + dex handles the pairing.
  2. Estimate each gene’s dispersion α, then shrink it toward the trend of α vs mean across all genes — borrowing strength, because 4 vs 4 is not enough to estimate a variance well.
  3. Fit the GLM; test β_dex = 0 with a Wald test (or a likelihood-ratio test).
  4. Adjust p-values with Benjamini–Hochberg (FDR).
  5. Optionally shrink log2 fold changes (lfcShrink) so that low-count genes do not top the list.

5 · ChIP-seq: designing the null

A ChIP-seq signal = specific binding (antibody × target TF) + non-specific binding (antibody × other proteins, open chromatin) + sonication bias (open chromatin shears more easily). A peak caller compares IP to a control and asks the Poisson question. Which control?

  • DNA input (sonicated chromatin, no antibody): corrects sonication bias only. Lots of DNA → deep, low-noise library.
  • Mock IP (IgG or no-target antibody, full IP protocol): corrects sonication bias and non-specific binding. Very little DNA → shallow, noisy library.

What “To mock or not” found (Xu et al., NAR 2021)

Using modERN datasets with matched IP, input and mock IP — 113 human (6 cell lines), 317 worm and 182 fly experiments:

  • Mock IP removes far more spurious sites than input: about 10 % of input-called peaks in human cell lines, but ~60 % in worm and ~88 % in fly (whole animals, many cell types).
  • Peaks that survive mock IP are more often real: motif enrichment rises 18–37 % in the top peaks.
  • But mock IP libraries are shallow and noisy, so used alone they lose sensitivity.
  • Recommendation: use both. Call peaks against input (sensitivity), then score each peak by how much stronger IP is than mock — a Bayesian posterior that uses all four libraries.

The posterior probability, in code

For a region with n_i reads in IP and n_d in input, θ₁ = IP fraction ~ Beta(n_i + 1, n_d + 1). For the mock experiment (n_m in mock IP, n_d’ in its input), θ₂ ~ Beta(n_m + 1, n_d’ + 1). A genuine peak needs θ₁ > 0.5 (enriched over input) and θ₁ > θ₂ (more enriched than mock). The paper computes P(θ₁ > 0.5 & θ₁ > θ₂) by integration; here we do it by simulation.

6 · The toolbox, in one table

You have… Ask… Tool
k of n reads carry an allele is θ = 0.5? what is P(θ > 0.5)? binomial test; Beta posterior
reads in a window vs background is this more than chance? Poisson tail test (MACS)
counts × replicates × conditions which genes change? NB GLM + shrinkage + BH (DESeq2/edgeR)
reads compatible with several isoforms how much of each? EM (RSEM, kallisto, salmon)
thousands of p-values how many are false? Benjamini–Hochberg FDR
a peak in IP is it in mock too? joint Beta posterior (Xu et al. 2021)
